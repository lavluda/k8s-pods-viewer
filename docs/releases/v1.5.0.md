# k8s-pods-viewer v1.5.0

`k8s-pods-viewer` v1.5.0 adds explicit AWS profile selection for users who
access EKS clusters with named AWS CLI profiles, brings provider-aware
node metadata into the node panel so mixed and multi-cloud clusters are
easier to read at a glance, and adapts the pod list to a multi-column
layout on wide terminals.

## Highlights

- added `--aws-profile <name>` to select a named AWS profile, such as `alex`
- added `AWS_PROFILE` environment variable support
- added `aws-profile=<name>` support in `~/.k8s-pods-viewer`
- the selected profile is used by both kubeconfig exec authentication and
  pod actions that invoke `kubectl`
- documented AWS profile usage and added release flag coverage
- detected node platform (EKS, GKE, AKS, Karpenter, or generic
  AWS/GCP/Azure/Kubernetes) from node labels and provider ID
- surfaced instance type, region/zone, node pool, and capacity type
  (on-demand vs spot) per node
- surfaced OS, architecture, OS image, kubelet version, and container
  runtime per node
- extended the node panel's detailed info toggle to show this metadata
  without adding a new keybinding
- pod list now spreads across multiple columns on wide terminals instead of
  paging sooner than the screen requires
- added `←`/`→` to move between columns and `pgup`/`pgdn` (or `[`/`]`) to
  change pages when the layout is multi-column
- the action popup now floats next to the selected pod's column instead of
  always anchoring to the right edge

## Notes

- AWS profile selection controls authentication only; Kubernetes RBAC still
  determines which namespaces, pods, nodes, and metrics the user can access
- CLI flags override environment variables, which override config file values
- existing behavior is unchanged when no AWS profile is specified
- node metadata fields are populated on a best-effort basis; providers do
  not consistently expose every label, so fields with no data are omitted
- bumped `k8s.io/apimachinery`, `k8s.io/client-go`, and `k8s.io/metrics`
  from 0.35.3 to 0.36.1
- on narrow terminals the layout stays single-column and `←`/`→` continue
  to page as before
